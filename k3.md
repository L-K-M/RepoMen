# k3 — RepoMen review

A thorough pass over the whole codebase (~2,800 lines Swift, 7 test files), read end to
end. Overall verdict: **the core is genuinely good.** The trust model (anchor proofs,
re-verify at reclaim time, `PathGuards` as the last line of defense, Trash by default)
is implemented exactly as PLAN.md describes, the pure logic is well factored and well
tested, and I found no crash-level bugs and no violation of the safety invariants.
What's here is mostly polish, one real safety gap, one real performance bug, and one
big missing feature (the one you asked for).

Items are numbered so they can be tracked into ANALYSIS.md. Status column at the
bottom says what got implemented where.

---

## 1. Bugs

### B1 — An empty scan result shows the *welcome* screen (high, UX)
`RepoMen/UI/DetailView.swift:12` shows `EmptyStateView` whenever `items.isEmpty &&
!isBusy`. `EmptyStateView` is the pre-scan welcome ("Repossess your disk… Scan Now").
So after a scan completes and finds nothing, the app looks exactly as if you never
scanned — no "your disk is clean" feedback, no record that a scan happened. Confusing
every time a regular user re-scans a clean machine.
**Fix:** show the welcome only in `phase == .idle`; add a distinct "nothing found"
state (last-scan-aware, with a Rescan button).

### B2 — Reclaiming unmeasured items reports "0 KB freed" (medium)
Checkboxes are live while sizes still stream in. If you check and reclaim items whose
measurement hasn't landed, `ReclaimSummary.freedBytes` sums their `sizeBytes == 0`
(`AppModel.swift:217`) and the alert proudly says you freed nothing. The bytes *were*
freed; the report is just wrong, and wrong numbers erode exactly the trust the app is
built on.
**Fix:** count unmeasured-but-reclaimed items in the summary and say the total is
understated (or measure synchronously for the checked set before reporting).

### B3 — Symlink bypass of the home-folder confinement (medium, the one real safety gap)
`PathGuards.validate` (`PathGuards.swift:31`) is purely textual, and
`Scanner.normalizedRoots` (`Scanner.swift:43`) only standardizes, never resolves. If a
scan root is a symlink — `~/Developer -> /Volumes/Archive/Developer` — every found
item has a path that *textually* sits inside home, passes validation, and gets
trashed on a different volume. The denylist also runs on the alias path, not the real
one. The anchors still re-verify, so this can't hit anything unprovable, but "inside
the home folder" is a documented invariant and it isn't one today.
**Fix:** resolve symlinks on scan roots at scan time, and re-validate the
symlink-resolved item path at reclaim time; refuse when resolution escapes home.

### B4 — Every rescan wipes the user's selection (low)
`AppModel.startScan()` clears `checkedIDs` (`AppModel.swift:94`). Item ids are stable
paths, so a selection can survive a refresh by intersection. Wiping it makes
"scan → check → rescan to see what changed" workflows needlessly tedious.
**Fix:** intersect the old selection with the new item ids instead of clearing.

### B5 — Filter doesn't match kind labels (low)
`visibleItems` searches `label` and `path` only (`AppModel.swift:62`). Typing "rust"
or "DerivedData" — the words the UI itself trains you on — finds nothing unless they
happen to appear in a path.
**Fix:** also match `kind.label`.

### B6 — No keyboard shortcut for Reclaim (low)
Scan is ⌘R, Stop is ⌘., but the second-most-important action is mouse-only.
**Fix:** ⌘⌫ on the Reclaim button.

### B7 — Notes, deliberately not fixed
- `SemanticVersion` compares prereleases lexically, so `beta.10 < beta.2`
  (`SemanticVersion.swift:57`). Edge case; the file is shared verbatim with the
  sibling apps, so a fix belongs upstream, not here.
- `UpdateChecker`'s skipped-version memory compares raw tag strings — fine in
  practice.

## 2. Performance

### P1 — The measurement stream invalidates the entire UI once *per item* (high)
This is the stutter you can feel. Every finished measurement hops to the main actor
and mutates the single `@Published items` array (`AppModel.swift:125-127, 167-172`).
Each mutation re-renders the whole view tree: `visibleItems` re-filters **and
re-sorts** the full array (`AppModel.swift:56-68`), every sidebar row recomputes an
O(n) `stats(for:)`, and the `Table` diff-runs. With ~500 artifacts that's 500 full
sorts + re-renders in a few seconds — janky scrolling, laggy checkbox toggles,
spinning fans. It gets *worse* the more there is to clean, i.e. exactly when the app
is most useful.
**Fix:** coalesce: background measurements go into a thread-safe buffer; the main
actor drains and applies them in one batch every ~120 ms (plus a final flush). Same
streaming feel, orders of magnitude fewer invalidations.

### P2 — Smaller, not worth separate fixes
- Scan-status text updates at 10 Hz re-render `DetailView`; harmless once P1 lands.
- `stats(for:)` is O(n) per row per render; fine after P1.
- `DirectorySizer` fetches 4 resource keys per file individually; bulk-fetch APIs
  exist, but on SSDs this is not the bottleneck. Leave it.
- `KnownCaches.items` runs after the walk finishes instead of concurrently;
  negligible.

## 3. Missing features

### F1 — Watched folders with age-based auto-clean (the flagship ask) ✅ implement
What you described: pick directories, set an age threshold, and RepoMen quietly moves
anything idle longer than that to the Trash on its own, from a menu-bar presence.
Design that stays inside the trust model:
- `WatchedFolder(path, maxIdleDays, isEnabled)`, persisted; managed in a new
  Settings → Watch tab.
- A `WatchManager` re-scans watched roots (reusing `Scanner`), measures, and
  auto-reclaims only items idle past that folder's threshold — **always to the
  Trash** (auto-clean never permanently deletes, regardless of the manual setting),
  always through `Reclaimer`'s re-verification and `PathGuards`.
- A pure, unit-tested `WatchEngine` decides eligibility: under watched root ∧ idle
  beyond threshold ∧ measured ∧ not excluded.
- Runs at launch (short delay) and every few hours while running; a `MenuBarExtra`
  (macOS 13 OK — deployment target is already 13.0) shows last run, reclaimed total,
  "Run Watch Check Now", "Open RepoMen". Quit-on-close yields while watching.
- A `UserNotifications` summary after each run ("Repossessed 2.3 GB from watched
  folders"), with a "notify only, don't trash" dry-run mode for the cautious.
- Full launchd background cleaning *while the app is quit* is the follow-up (F2) —
  it needs a login-item helper and is a bigger trust surface.

### F2 — True background cleaning via launchd/login item (deferred)
The natural F1 follow-up. Needs SMAppService login item or a LaunchAgent plist,
headless scan+clean, and very conservative defaults. Design exists; not this round.

### F3 — Deferred, good candidates
- Auto-scan at launch (off by default). Cheap; folded into F1's PR as a pref.
- Per-category "Select idle" / kind filter chips above the table.
- Exclusion by pattern ("never suggest `.venv` under ~/work").
- Export findings (CSV/Markdown) for the "show me what you found" crowd.
- Group-by-repo rollup: "Baegun: 12.4 GB across 6 artifacts" — great insight, real
  work (repo-root detection).
- Extra Table columns (category, full path) as optional toggles.

## 4. Visual & layout

- **V1** Settings tabs jump height between tabs: Rules is pinned to 440 pt
  (`SettingsView.swift:133`), the others size themselves. Give the tab view a
  consistent frame. (Fixed in F1's PR — it adds a Watch tab there anyway.)
- **V2** The browser-running warning is a full sentence rendered inline in the table
  row (`ItemTable.swift:72-77`) — it wrecks the row layout on narrow windows. Show
  just the triangle icon, sentence moves to the tooltip.
- **V3** Sidebar rows show bytes but not counts; counts answer "how much *stuff*".
  Cheap, deferred.
- **V4** The reclaim confirmation and summary dialogs are functional but plain; the
  summary should offer an "Open Trash" button (see I2).

## 5. UX & convenience

- U1 = B4 (selection survives rescans). U2 = B6 (⌘⌫). U3 = B5 (search by kind).
- U4: The reclaim summary is an alert you must dismiss; fine at this size, but see I2.
- U5: After a reclaim, items vanish from the list silently — correct, and with B2
  fixed, reported accurately.

## 6. Novel / delightful

- **I1 — Lifetime repossession counter.** Persist cumulative reclaimed bytes; show
  "148 GB repossessed all-time" in the footer and the menu-bar label. Gamifies the
  core loop, costs almost nothing. (Implemented with F1.)
- **I2 — "Open Trash" button in the reclaim summary** — closes the "wait, I need
  that back" loop in one click. (Implemented in PR 1.)
- **I3 — Lean into the theme.** The repossession conceit is good; watch notifications
  can serve "eviction notices" ("14 squatters evicted from ~/Projects — 2.3 GB
  repossessed"). Copy-only, keeps the tone without getting cute about deleting things.
- **I4 — Repo leaderboard (deferred):** the group-by-repo rollup from F3, framed as
  "your most expensive repo". People *love* blaming a specific project.
- **I5 — First-run "biggest single win" banner** after the first scan ("DerivedData ·
  Xcode is holding 31 GB — one checkbox away"). Deferred; needs B1's clean-state
  groundwork.

## 7. The Chrome full-screen/split-mode URL note

Not applicable to this codebase: RepoMen has no browser automation, no URL handling,
and no forms — nothing here "talks to Chrome" or saves anything into it. The only
browser contact is enumerating `~/Library/Caches/<vendor>` folders and checking
bundle IDs against `NSWorkspace.runningApplications`. This symptom belongs to a
different app (a browser companion — the sibling menu-bar app, perhaps?). Point me at
that repo and I'll dig in.

## 8. The name

"MacDring" appears nowhere in this repo — the app is **RepoMen** — so I'll assume the
question is about this app's identity going forward. RepoMen is honestly strong (git
*repos* + *repossession* in one word). If you want to move anyway, brainstorm:

- **Sawdust** — my pick. Sawdust is *exactly* what building software leaves behind:
  harmless, regenerable, and it piles up. Friendly, memorable, great icon potential
  (a broom, a dust cloud), and it sounds like care rather than aggression — which is
  the app's whole pitch.
- **Rubble** — build rubble. Short, punchy, slightly more aggressive.
- **Offcuts** — workshop leftovers. Classier, more obscure.
- **Jetsam** — jettisoned cargo, *and* macOS's own memory-pressure killer (jetsam
  events). A dev in-joke, but possibly confusing with the system facility.
- **Ballast** — what you jettison to go faster. Positive framing.
- **Flotsam** — floating debris. Pairs with Jetsam; softer.
- **Reclaim** — the verb the app already uses everywhere. Descriptive, a bit plain.
- **Detritus** — accurate, sounds unpleasant.
- Keep **RepoMen** — if the dislike is of "MacDring" specifically, you may already be
  done: the name in the repo is good.
