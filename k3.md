## 1. Open findings (new, against current main)

### K1 — Rescanning wipes the user's selection 🟡
`AppModel.startScan()` still does `checkedIDs = []` (`AppModel.swift:136`). Item ids
are stable paths, so a rescan can preserve the selection by intersection. Today,
"check a few things → rescan to see what changed → notice your checks are gone" is a
real papercut, and it quietly contradicts the "selection survives size updates"
comment on `CleanableItem`. → **implemented (PR k3/ux-remainder)**

### K2 — Reclaim *summary* still understates freed bytes for unmeasured items 🟡
fable B8 was fixed on the input side (confirmation/footer show "at least X"), but the
post-hoc alert still does `Reclaimed N items — \(freedBytes)` with `sizeBytes == 0`
for anything reclaimed before sizing finished (`AppModel.swift:346,351-361`,
`DetailView.swift:255-272`). Trashing a 5 GB `target/` mid-measure still earns you
"Zero KB moved to the Trash" — the honesty fix stops one dialog too early.
→ **implemented (PR k3/ux-remainder): summary says "at least X" and names the count.**

### K3 — The running-app warning is still a full sentence inside the row 🟡 (visual)
`ItemTable.swift:76-82` renders `Label(warning, …)` — icon *and* the whole "Chrome is
running — quit it before reclaiming" inline, fighting the actual item label for
width. PR #6 added truncation + tooltip, which keeps it safe but not sane. Icon-only
in the row; the sentence already lives in the tooltip and the confirmation dialog.
→ **implemented (PR k3/ux-remainder)**

### K4 — Derived state is recomputed per access (== ANALYSIS P4/P5/P7) 🟠
Open in ANALYSIS.md; the shape described there is right. Implementing it:
`visibleItems` cached behind a dirty flag driven by `didSet` on its inputs,
per-entry stats precomputed on `items` mutation, `checkedItems` via an id→item map
(deterministic path order), search debounced ~150 ms. Public API unchanged.
→ **implemented (PR k3/derived-state-perf)**

### K5 — No watched-folders / auto-clean mode (the flagship request) 🔴 feature
The ask: mark directories, give them an age threshold, and RepoMen keeps them clean
on its own — Trash only, with a menu-bar presence. PLAN.md currently lists
"scheduled/background cleaning" as a non-goal and ANALYSIS I14 rejected menu-bar
totals; **the product owner has now explicitly requested this**, which overrides the
non-goal. Design that keeps the trust model intact:
- `WatchedFolder(path, maxIdleDays, isEnabled)`, persisted (JSON in UserDefaults).
- A pure, unit-tested `WatchEngine` decides eligibility: item under the most specific
  enabled watched folder ∧ measured ∧ idle past that folder's threshold.
- `WatchManager` (main-actor): check 30 s after launch + every 6 h, detached
  scan→measure→decide, then `Reclaimer.reclaim(…, .trash)` — auto-clean is **always
  Trash**, never permanent delete, always fully re-verified. Quit-deferral covers
  auto-reclaims exactly like manual ones.
- Master switch **off by default** ("Nothing is pre-selected" extends to automation:
  until you flip it, watch mode only *reports*). Dry-run reports are deduped by a
  candidate-set signature so identical findings don't re-notify every 6 h.
- `UNUserNotificationCenter` summaries in the repo-man voice ("14 squatters evicted
  from ~/Projects — 2.3 GB repossessed"); silent when nothing happened.
- `MenuBarExtra` (deployment target is already 13.0): last run, reclaimed total,
  "Run Watch Check Now", "Open RepoMen", Quit. Quit-on-close yields while any watch
  folder is enabled so the watcher actually stays alive.
- Settings → Watch tab: folder list with per-folder day thresholds, quick-add from
  current scan roots, master toggle, "Check Now", last-run readout.
- PLAN.md non-goal amended; README and AGENTS.md layout updated.
→ **implemented (PR k3/watch-folders)**

### K6 — No scan-at-launch option 🟡
Small automation that pairs naturally with K5: opt-in preference (default off) +
General tab toggle; ContentView triggers one scan when idle at launch.
→ **implemented (PR k3/watch-folders)**

### K7 — Row actions are context-menu-only (== ANALYSIS U10) 🟡
"Exclude from Future Scans" is effectively invisible. An **Items** menu bound to the
table selection — Reveal in Finder (⌘↩), Copy Path (⇧⌘C), Check/Uncheck, Exclude (⌘E)
— makes the actions discoverable and Help-searchable. Selection lifts from
`ItemTable`'s private `@State` into the model so menu and context menu share it.
→ **implemented (PR k3/ux-remainder)**

## 4. The name

"MacDring" appears nowhere in this repository — the app is called **RepoMen**, which
is honestly a strong name (git *repos* + *repossession* in one word). If the itch is
real anyway, my shortlist:

- **Sawdust** — my pick. Sawdust is exactly what building software leaves behind:
  harmless, regenerable, forever piling up. Friendly, memorable, great icon potential
  (a broom; a dust cloud over a hard drive), and it sounds like *care* rather than
  aggression — which is the app's entire pitch over the brute-force cleaners.
- **Rubble** — build rubble. Short and punchy, slightly more menacing.
- **Offcuts** — workshop leftovers. Classier, more obscure.
- **Jetsam** — jettisoned cargo *and* macOS's own memory-pressure terminator. A great
  dev in-joke; confusing with the system facility.
- **Ballast** — what you drop to go faster. Positive framing.
- **Flotsam** — drifting debris. Softer; pairs with Jetsam.
- **Reclaim** — the verb the UI already speaks. Descriptive but plain.
- Keep **RepoMen** — if "MacDring" was the name you disliked, you may already be
  done; the repo's actual name is good.
